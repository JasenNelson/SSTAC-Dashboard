## 5. Observations on the base DDL (reported, not changed)

- In the base draft service_role keeps default table privileges and the base
  revokes the RPCs from service_role. This activation file (B4) additionally (B5) runs
  REVOKE ALL on the 3 tables FROM service_role, GRANT SELECT on them, and REVOKE ALL on the
  events sequence FROM service_role (SELECT kept), see section 7 M7.
- `DROP POLICY IF EXISTS` / `DROP TRIGGER IF EXISTS` before CREATE tolerate
  leftovers silently while tables/functions use plain CREATE; PREFLIGHT proves
  a clean slate so this cannot mask anything.
- The admin helper depends on `public.user_roles(user_id, role)` and
  `auth.uid()`; PREFLIGHT checks both. `regexp_count` needs PG15+.
- The write RPCs are SECURITY DEFINER with `search_path = public, pg_temp`
  (pg_catalog implicit first). Leg 1a R1 finding I1: base VERIFY V14 is now
  ported (PREFLIGHT rows 30-32, VERIFY rows 81-83), see section 7.
- Seeds are per-release and immutable here; a future release needs its own
  file. NOTIFY is also in KILL_SWITCH and ROLLBACK so PostgREST drops stale
  function routes.

M4 -- ROLLBACK ordering: apply the KILL_SWITCH before the ROLLBACK. ROLLBACK locks events, responses, questions in that order; the RPCs take locks in the opposite order, so a concurrent write can deadlock with the rollback. The deadlock is fail-safe (one side aborts, nothing is dropped).

M6 -- blank-submit regex: the RPC uses `[[:space:]]` plus explicit Unicode code points; `[[:space:]]` depends on the database locale/collation. If the locale classifies an extra code point as space (for example U+0085 or U+180E under some libc builds) that JavaScript `trim()` keeps, the app would accept text the database rejects as blank_submission (HTTP 422). UX-only; no data or security impact.
